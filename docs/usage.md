# 使用与配置

[返回 README](../README.md) · [构建指南](development.md)

## 第一次聊天

1. 安装 Debug APK 或从 Android Studio 运行应用。
2. 打开设置，在「API Key 管理」中添加服务商密钥，或者使用「Sign in with ChatGPT」完成账号授权。自定义 OpenAI 兼容服务需配置对应端点与凭据。
3. 在「模型选择」中，为快速廉价角色 `FAST_CHEAP` 选择服务商和模型。只填写 API Key 不等于完成模型选择。
4. 返回聊天界面发送一条简单消息，确认服务商和模型可用。
5. 再根据用途配置规划、视觉、设备权限、搜索和 Linux 环境。

ChatGPT 登录使用 OAuth 会话，模型可用性取决于登录状态和实际服务端授权结果。不要把 OAuth token 填入 API Key 输入框。

## 四种模型角色

| 角色 | 配置用途 |
| --- | --- |
| 快速廉价 `FAST_CHEAP` | 主聊天入口，需要优先配置 |
| 复杂规划 `COMPLEX_PLANNING` | 复杂任务规划、设备与 Linux 执行推理 |
| 快速视觉 `FAST_VISION` | 日常图片理解 |
| 复杂视觉 `COMPLEX_VISION` | 复杂任务中的视觉分析 |

可以复用同一个支持相应能力的模型，也可以按成本和能力分别选择。模型必须实际支持所用工具或图片输入；模型列表中的能力元数据可能不完整。

API Key 服务商、自定义端点和 ChatGPT 登录的配置方式不同，但模型角色都通过统一的模型选择入口绑定。登录过期、密钥被移除或端点不可达时，应先恢复服务商就绪状态。

## 会话与附件

聊天支持多个独立会话、历史消息、文件及图片附件。切换或新建会话不会主动终止其他会话正在运行的任务。

应用会保存会话快照；进程被系统结束后，恢复历史不等于继续执行之前的任务。附件的访问还受 URI 授权、原始文件是否存在及内部复制状态影响。

人设、Agent 步数、输出显示及安全配置可在设置中调整。排查异常时，先用简单消息和少量工具调用确认基础路径，再逐步增加任务复杂度。

## Android 设备能力

普通聊天无需先开启全部特权能力。按实际要使用的工具配置：

| 能力 | 主要用途与条件 |
| --- | --- |
| Shizuku | 通过运行中的 Shizuku 服务并完成授权，提供 Shell 或 Root 身份能力 |
| Root Shizuku | 需要 Shizuku 实际运行在 UID 0，普通 ADB 模式不满足 |
| 直接 Root | 需要设备具备可用的 `su` 授权 |
| Dhizuku | 依赖设备管理环境及相应授权 |
| 无障碍服务 | 提供部分界面读取、操作与回退路径 |
| 所有文件访问 | 文件管理工具需要的存储能力 |
| 使用情况访问 | 查询应用使用情况 |
| 修改系统设置 | 调节屏幕亮度、自动亮度模式和息屏超时 |
| 音量控制 | 普通音频权限随应用安装获得，调节结果受设备音量和勿扰策略限制 |
| 悬浮窗 | 显示在其他应用上层的相关能力 |

`pressKey` 归入 `key_input`，需要 Shizuku 或 Root。无障碍可用 `performGlobalAction` 执行返回、主页等系统动作。

实际能力由系统版本、设备实现、权限状态、工具后端及会话授权共同决定。敏感操作还可能受应用安全配置拦截。连接或授权发生变化后，先检查设置中显示的状态，再重试相关工具。

## Linux 环境

项目内置 PRoot 原生程序和 `debian-rootfs.tar.zst` 归档。rootfs 初始化会写入应用私有存储，应预留归档解包所需空间。

可在设置中查看 rootfs 状态、导入自定义初始化归档或使用终端。自定义归档需要与设备 CPU 架构匹配；APK 同时包含两种原生 ABI，不意味着一个 rootfs 归档能同时支持两种架构。

PRoot Linux 使用全局共享 rootfs。Agent 可能安装软件或修改其中的配置；重置 rootfs 会清除其中的数据与改动，执行前应保存需要保留的文件。

## 端侧 TinyModel

TinyModel 是内部事务使用的轻量模型，与四个云端/服务商角色配置分开管理。仓库包含内置 `.litertlm` 模型，也支持本地导入。

- **AUTO**：根据模型能力尝试 GPU，初始化失败时回退 CPU。
- **GPU**：强制 GPU，设备驱动或模型不兼容时可能失败。
- **CPU**：使用 CPU 后端。

首次使用可能需要模型解包与引擎初始化。遇到 GPU 初始化失败时可切换 CPU 对照验证；模型可加载不代表其输出质量适合所有内部任务。

Linux 环境可通过 `127.0.0.1` 上的本地 HTTP 桥接访问 TinyModel，无需令牌。`maid-tiny "提示词"` 可直接生成，`cat file.txt | maid-tiny` 可从管道读取。使用参数提示并追加管道内容时传入 `--stdin`。桥接是进程内运行能力，应用进程退出后不保证继续可用。

## 联网调研

调研工具支持通用网页、学术、代码与 Issue、技术社区和百科分类。网页阅读可提取正文或读取原始文本；实际可用性取决于网络、搜索引擎限制及实例配置。

SearXNG 可以使用配置的实例，项目也有本地 PRoot 服务管理。修改实例地址或网络后，可能需要刷新配置与可用性状态。某个分类失败时，其他分类的可用引擎不一定能替代它。

## 数据提醒

API Key 和 OAuth 敏感数据通过加密存储保存；会话、附件、长期记忆和 rootfs 应分别看待。使用云端模型、搜索和网页阅读时会产生外部请求，图片、文件或工具结果是否被发送由实际任务流程决定。
